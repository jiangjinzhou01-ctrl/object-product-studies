# OBJECT / Product Studies — Case Study

## 项目目标

构建一个围绕真实消费科技产品的独立体验网站，展示产品信息组织、视觉设计、交互实现与工程交付能力。产品名称用于事实说明；项目与 Apple 无隶属、赞助或认可关系，也不是商业委托案例。

## 设计定位与视觉研究

产品画面是页面的主体。设计研究关注设备的轮廓、材质、比例和实际使用场景，将产品名称、图像尺度与阅读顺序一起规划。

视觉系统以黑、白和中性灰为基础。酒红与冷蓝只出现在相应产品章节，与真实硬件或屏幕画面建立联系。首页采用整幅设备构图，随后通过明暗场景切换、产品目录、专业设备、轻薄设备与摄影样张改变阅读节奏。iPhone 和 Mac 各自拥有产品故事的开场与章节构图。

排版采用 Inter Variable 与本地 Noto Sans SC 400 / 600 字重。中文字体仅包含当前公开界面中的字符，保留系统字体回退。标题、正文、参数和图注有明确层级；正文行宽与字号以阅读为先。间距、颜色和动效时长通过 CSS Tokens 维护。

## 事实与素材研究

五款设备为 iPhone 18 Pro、iPhone 17、14 英寸 MacBook Pro 基础 M6、13 与 15 英寸 MacBook Air M5。规格关联官方来源 URL 与核查日期；缺乏可靠依据的参数保持省略。图像按准确型号和来源使用，Pro / Pro Max 合照明确注明。

20 项图像来自 Apple Newsroom 与技术支持资料，按用户要求用于独立作品集并完整记录版权边界。本站不宣称开放许可或独立图像授权，不生成硬件、不重着色、不伪造旋转。详细来源见 asset-register.md、product-research.md。

三张 Mac Support PNG 的透明留边经过裁切，设备像素没有重绘。清单同时保存原始 1000 × 1000 尺寸和裁切后的尺寸，避免大段空白缩小设备的实际展示比例。

## 信息架构

首页承担发现，系列页面帮助理解型号关系，产品故事展开设计与使用场景，比较工具支持具体选择。两篇设计观察、Case Study 与来源索引补充事实和项目说明。

主内容包括首页、iPhone 系列、iPhone 18 Pro、Mac 系列、MacBook Pro M6、比较、项目、素材与两篇文章。未知路径有返回入口；旧 Mac 地址转向当前系列。没有购物、支付、库存或账号登录流程。

## 交互系统

- **首屏视角**：真实配色合照与正背面合照切换，画框尺寸保持稳定，预加载另一张图像。视角不会冒充单一型号的假 360°。
- **滚动叙事**：IntersectionObserver 追踪三个内容章节，协调 Sticky 图像与正文。移动端缩短视觉高度，留出实际阅读区。
- **相机场景**：风景、夜色、低光标签切换对应官方样张与说明，明确拍摄来源和测试边界。
- **Mac 工作流**：动态影像、视觉设计、开发构建切换对应软件场景、图片与文字，不伪造性能测试。
- **真实接口点选**：在官方两侧接口图上标注可点击位置，同步更新 Thunderbolt 4、HDMI、SDXC、充电和音频说明；下方标签同时提供键盘入口。
- **产品探索与比较**：探索器选择实际型号并进入详情；比较支持同类双槽位、替换、交换、清空、重置与差异筛选。URL 恢复分享状态，非法或重复型号被清理。缺失参数不被当作已知差异。
- **分享与键盘**：剪贴板失败时提供可选中的链接。标签组支持方向键与 Home / End，导航抽屉支持焦点循环、Escape、返回触发器与滚动锁定。

## 技术架构与工程难点

React、严格 TypeScript、Vite 和 React Router。产品采用手机 / Mac 判别联合，产品、来源、媒体与页面职责分开。首页直接加载，其他页面按路由拆分。共享组件承载导航、媒体、规格和通用入口；相机场景单独管理实际状态。

图片渲染必须同时考虑源尺寸、实际设备范围和容器构图。透明裁切后重新计算 srcset 宽高，保留原始尺寸追溯，避免仅放大带留边的整张 PNG。硬件合照、单一型号与官方样张保持明确的内容身份。

HashRouter 为 GitHub Pages 保留刷新与分享能力，所有图片、字体和链接按实际 Vite base 生成。main 更新经类型检查、Lint、格式检查、构建和浏览器测试后部署。

## 响应式策略

桌面使用整幅产品舞台、并置叙事和宽图；移动端重新安排标题、图片和操作顺序。设备目录改为可触控的横向选择，导航使用原生 dialog。

比较表在移动端按“规格名称 + 两侧数值”重排，两个型号同时可见，滚动时保留型号表头，避免读者在两列之间反复横向移动。测试宽度为 360、390、430、768、1024、1440、1920px。

动效使用 CSS、IntersectionObserver 与 Web Animations API，优先 transform 与 opacity，核心功能不依赖动画，并尊重减少动态效果偏好。

## 性能与测试

73 个本地 WebP 派生版本按实际宽度提供 srcset / sizes，不放大原始素材。首屏高优先级，其他图像懒加载；图集和场景预加载相邻目标。中文字体是本地子集，构建与部署不依赖远程字体服务。

40 项 Playwright 用例覆盖内容、资源、导航、图集、首屏视角、相机场景、工作流、接口、比较、URL、七种视口和 axe 规则。截图逐项用于人工构图复核，没有宣称逐像素基线回归。最新执行结果与 Lighthouse 的测量范围见 qa-results.md。

## 后续方向与限制

目前为 Chromium 桌面与移动视口模拟，尚未完成真实 iOS / Android、Safari / Firefox 或屏幕阅读器实机验证。后续优先做真实设备测试与小样本任务观察，再依据阅读和比较行为调整章节密度，并补充明确授权的独立摄影。自动化分数不能代替视觉判断或用户研究。
